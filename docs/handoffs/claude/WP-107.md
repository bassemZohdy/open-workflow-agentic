## 1. Answer: is `CallerContextResolver` + `Pep.decide(DATA_ACCESS)` enough for ingress?

**Yes, for the current increment.** No new typed hook, claim or caller type is required.

* Verified provenance only (UNVERIFIED refused); tenant, subject and scopes come from the verified token.
* One `DATA_ACCESS` decision per receipt, scoped to the target instance, with scope `oa.events.receive`; every decision is audited
  by `Pep`; an unavailable engine or audit sink refuses (503); `DATA_ACCESS` never uses safe recovery.
* The exact deployment binding (tenant, kind, subject, source, type, correlation, definition) is enforced in `EventIngress`
  independently of Cedar, so a permissive policy cannot widen it.
* `docs/policy.md` section 2 now lists the event receipt request and documents the limits (route resource is a hash).
