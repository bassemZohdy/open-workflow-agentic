## Delivered interface and failure behavior

InboxMessage is a framework-free normalized event envelope. The trusted ingress
supplies tenant, instance and stable wait occurrence/correlation key. Identity
is tenant + CloudEvents source + event id. It is bound to a fingerprint of all
content/routing; conflicting reuse fails before matching. JSON text is immutable,
validated and limited to 64 KiB. Ingress must normalize equivalent JSON before
retry; source is a URI-reference. Identity byte size fits the database key.

JdbcEventInbox.receive commits the message before any matching/wake. A duplicate
returns the original deadline and never extends retention (maximum 30 days).
Early events survive a new component/process because state is in PostgreSQL.
The component is internal; no unauthenticated ingress or network call is added.

match requires WAITING and an unexpired persisted wait deadline under the same
task.instance row lock used by lifecycle changes. A cancellation or terminal
state committed first prevents a new signal. Matching writes a durable signal
for exactly one event and one stable logical wait occurrence, ordered by local
receipt sequence, independent of untrusted producer timestamps. Duplicate
matching returns that signal. Expired events and wrong correlation/type cannot
create a new signal; waits with another type cannot reuse an existing key.
Matching does NOT publish to Flow, acknowledge a business effect or claim that
an in-memory listener received anything. A signal must remain recoverable until
the future adapter atomically persists its consumption of that signal.
