## Delivered interface and failure behavior

InboxMessage is a framework-free normalized event envelope. The trusted ingress
supplies tenant, instance and stable wait occurrence/correlation key. Identity
is tenant + CloudEvents source + event id. It is bound to a fingerprint of all
content/routing; conflicting reuse fails before matching. JSON text is immutable,
validated and limited to 64 KiB. Ingress must normalize equivalent JSON before
retry; source is a URI-reference. Identity byte size fits the database key.

JdbcEventInbox.receive commits the message before any matching/wake. A duplicate
returns the original deadline and never extends retention (maximum 30 days).
Early events survive a new component/process because state is in PostgreSQL.
The component is internal; no unauthenticated ingress or network call is added.

match requires WAITING and an unexpired persisted wait deadline under the same
task.instance row lock used by lifecycle changes. A cancellation or terminal
state committed first prevents a new signal. Matching writes a durable signal
for exactly one event and one stable logical wait occurrence, ordered by local
receipt sequence, independent of untrusted producer timestamps. Duplicate
matching returns that signal. Expired events and wrong correlation/type cannot
create a new signal; waits with another type cannot reuse an existing key.
Matching does NOT publish to Flow, acknowledge a business effect or claim that
an in-memory listener received anything. A signal must remain recoverable until
the future adapter atomically persists its consumption of that signal.

## Structured HTTP ingress increment

POST /instances/{instance}/events/{correlation} accepts application/cloudevents+json.
The route comes from transport metadata; tenant and subject come from the merged
CallerContextResolver. Event extensions and forged headers cannot override them.
The complete CloudEvents 1.0 envelope is stored as canonical JSON in data_json,
including optional attributes and binary data_base64, so later replay has its
original metadata. Objects are sorted recursively, array order and exact decimal
values are preserved. JSON is limited to 64 KiB, depth 64, number length 128;
duplicate members, trailing tokens and malformed UTF-8/surrogates are refused.
The official CloudEvents SDK validates the envelope. Binary HTTP mode and batches
are not exposed by this route; 415 is returned for unsupported content types.

Ingress uses the existing public Pep.decide DATA_ACCESS path, with target instance
as taskId, caller scopes and a domain-separated hash of tenant/source/type/wait as
resource. No PolicyContext field is repurposed and no Claude-owned code is edited.
A separately qualified PEP loads policy/events from GPT-owned application config;
it neither replaces the operations PEP nor exposes a global PDP for audit access.
The reference policy checks oa.events.receive. An additional immutable deployment
binding must match tenant, verified subject kind/id, exact source/type, target
definition and correlation occurrence. Empty bindings deny every receive. An
administrator can narrow the policy by exact route hash as well. Binding hashes
are recorded in central audit. Missing/unavailable policy yields 503 with no
receipt; there is no safe-recovery fallback for DATA_ACCESS.

Audit attempt is durable before receipt, and accepted/duplicate outcomes are
recorded afterward without raw payload or credentials. If the result audit fails,
503 tells the producer to retry the same source/id; the committed receipt remains
deduplicated. Metrics use fixed outcome labels only. HTTP returns 202 for a new
receipt, 200 for an identical retry, 409 for conflicting content/route, 404 for
another tenant or absent target, 400/413/415 for malformed/oversized/unsupported
input and 403 for denied/unbound producers. A receive response is not an engine
acknowledgement. No in-memory Flow publisher is called.

Configuration example and defaults are in application.properties. Bindings are
validated at startup, bounded to 256 producers with 1..64 entries per route set,
and frozen for the process lifetime. A shared .gitattributes rule preserves LF
for hashed Cedar policy files across platforms without changing applied data.

## Producer-route privacy ordering

Producer identity/source/type/correlation binding is checked before target lookup.
An unbound producer therefore receives the same 403 for an existing or unknown
id and cannot probe target existence. For an otherwise bound producer, a target
outside its tenant or allowed definitions is indistinguishable from an absent
target (404). HTTP tests configure a valid producer in a second tenant to prove
lookup scoping independently of producer denial. A unit assertion proves that
unverified, unbound and policy-denied requests perform zero target reads. These
changes do not weaken policy or receipt guards and require new current-head CI.
