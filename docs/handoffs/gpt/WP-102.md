# WP-102 H1/H2: Keycloak compatibility and Java CI

Related: Claude PR #39 and its `docs/handoffs/claude/WP-102.md`.

## H1 decision

ADR 0021 now chooses strict native actor-bearing delegation. Missing `act` is
still a refusal. Stable-standard exchange is tested as an actorless-token
rejection case, not silently accepted as delegated authority. Native delegation
is an explicit preview compatibility profile; production acceptance is separate.
This avoids introducing a new STS or weakening the existing guard.

Claude implements the ADR checks in its owned exchanger/verifier/guard code and
tests: independently verified input identity/expiry; exact effective user,
issuer-scoped service-account actor, tenant, requested audience/scope; complete
active grant chain; actual JWT lifetime bounded by verified subject/grant/300s;
no refresh token; one-use replay; policy/audit failure closed. Re-check grants
after the exchange response. OAuth error strings are diagnostic; never turn a
non-success HTTP response into success because its error name differs.

Do not locally shorten only `IssuedToken.expiresAt` while keeping an overlong
bearer. Reject that bearer. Do not replace consent with a production hardcoded
`may_act` mapper. An issuer service-account UUID and an OAuth client ID are
different identifiers. Multi-hop chains that the provider cannot preserve are
denied until their complete chain semantics are implemented and tested.

## H2 CI contract

GPT-owned files:

- `.github/workflows/keycloak-interop.yml`: two isolated, pinned Keycloak jobs,
  localhost-only endpoint, disposable admin credentials, PostgreSQL 16, Java 21,
  Maven Failsafe, bounded startup/job time and cleanup.
- `tools/require_keycloak_evidence.py`: preflight checks the selected real Java
  source exists; postflight requires profile-matching failsafe XML and every
  required Java case passing. Missing, errored, failed and skipped cases fail.
- `tools/test_keycloak_evidence.py`: regression tests of false-evidence rejection.

Claude supplies these files in its registered test area (GPT does not edit them):

`apps/app-runtime/src/test/java/io/github/bassemzohdy/openworkflow/agentic/identity/`

| Job | Pinned image | Required Java class and methods |
|---|---|---|
| `standard` | `quay.io/keycloak/keycloak:26.2.5` | `KeycloakStandardIT`: `realIssuerSignatureAndAudienceAreVerified`, `actorlessExchangeIsRejected` |
| `delegation` | `quay.io/keycloak/keycloak:26.8.1` | `KeycloakDelegationIT`: `nativeDelegationPreservesAuthorityBounds`, `invalidActorIsRejected`, `revokedOrExpiredGrantIsRejected`, `subjectExpiryBoundsIssuedCredential`, `issuerKeyRotationIsHandled`, `delegationRequiresPermissionAndConsent` |

The first image is a regression baseline for the observed incompatibility, not
a production-version recommendation. The second job alone enables
`token-exchange-delegation,parameterized-scopes`.

Environment: `KEYCLOAK_URL=http://127.0.0.1:18080`, `KEYCLOAK_PROFILE`,
`KEYCLOAK_ADMIN_USER`, `KEYCLOAK_ADMIN_PASSWORD`. Maven additionally supplies
`-Dkeycloak.required=true -Dkeycloak.profile=<profile> -Dkeycloak.url=<URL>`.
Java tests must not skip when `keycloak.required=true`; fail if setup is absent
or the server cannot be reached. Failsafe XML must contain the matching
`keycloak.profile` property. Never log tokens/client secrets in reports.

The Java fixtures create uniquely named disposable realms on this isolated
server, establish users, clients, role/audience/scope mappers and (for native
delegation) real permission/consent setup. They exercise the actual
`Rfc8693TokenExchanger`, `JwtTokenVerifier` and `ResourceTokenGuard`, not a raw
HTTP-only reproduction or the fake issuer. Assert unavailable JWKS/rotation,
wrong actor/tenant/audience, widened scopes, expiry, revocation and replay denial
within the listed cases. Fixed `may_act` claims alone do not prove consent.

Run locally against an isolated server, for example:

```bash
export KEYCLOAK_URL=http://127.0.0.1:18080 KEYCLOAK_PROFILE=delegation
export KEYCLOAK_ADMIN_USER=admin KEYCLOAK_ADMIN_PASSWORD=ci-keycloak-only
python3 tools/require_keycloak_evidence.py --profile delegation --preflight
mvn -B -pl apps/app-runtime -am verify -Dit.test=KeycloakDelegationIT \
  -Dfailsafe.failIfNoSpecifiedTests=false -Dkeycloak.required=true \
  -Dkeycloak.profile=delegation -Dkeycloak.url="$KEYCLOAK_URL"
python3 tools/require_keycloak_evidence.py --profile delegation
```

The workflow provides the corresponding `docker run` command; dispatch it or
run the same commands against the disposable local Docker container. A missing
Java class currently fails preflight deliberately. That is an open consumer
handoff, not passing real-provider evidence. Combine this infrastructure and
Claude's reviewed test changes before requesting merge; both exact-head review
and green CI remain required. Keep WP-102 partial until the entire real Java
matrix and remaining deliverables are evidenced.
