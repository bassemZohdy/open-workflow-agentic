# WP-106: explicit targeted human wake dispatch

`HumanWakeDispatcher` composes the existing isolated human-decision journal, staged reference event, owned inbox reservation and SDK checkpoint marker for one captured SDK registration. It verifies the exact application, workflow, task position and iteration, rejects correlation predicates, evaluates the actual SDK predicate, stages only a matching retained decision, reserves under the current task claim, installs the marker, and checks the registration and live claim again before invoking that one callback. It does not broadcast the event. A bounded in-process gate prevents concurrent calls for the same task through one dispatcher instance; durable reservations and the checkpoint fence remain necessary across instances and processes.

`DISPATCHED` means only that the callback returned; the actual SDK task checkpoint and receipt proof, acknowledgement and post-checkpoint authority gate must still succeed before continuation. A failed or uncertain reservation is not automatically retried under the same owner epoch. The caller must use the same approved datasource for the stage, owner and guarded JPA writer and supply the actual live registration. This is an explicit prototype against `human_proposal`, with no CDI, endpoint or scheduler wiring. It does not authenticate an actor, approve a decision, establish current workflow owner authority or supply an approved production policy, listener registry or production human-task schema.

The application test uses the real SDK and JPA writer with fixture approval: it proves a registration for another instance is refused without staging, concurrent calls to the same task return BUSY, the selected callback creates a real checkpoint and does not wake the other instance, and a claim released during blocking reservation audit prevents the callback and checkpoint. Existing separate-process tests continue to exercise checkpoint recovery, but the new dispatcher itself is not production-wired or an end-to-end T02 proof. General listen strategies, production authorization, distributed callback coordination and supported recovery/activation remain open.
