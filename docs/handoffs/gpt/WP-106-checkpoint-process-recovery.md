# WP-106: checkpoint recovery across processes

Checkpoint recovery now appends its `event.checkpoint.observed` audit and changes the delivery to `ACKNOWLEDGED` in one local PostgreSQL transaction. It first locks and checks the pinned registry instance and retained receipt, then appends the audit and updates the delivery on that same connection. A failed audit, update, or transaction rolls both back. Concurrent recovery sees an existing acknowledgement and does not append a second audit. A lost commit reply is resolved by retrying against the retained acknowledgement; it is not treated as proof that a commit failed.

The isolated human test stages an audited decision, delivers its exact retained event to the pinned SDK, and waits for the real JPA task checkpoint and matching receipt proof. A separate JVM appends the recovery audit and halts before updating the acknowledgement: both writes remain absent while the checkpoint remains consumed. A fresh process then repairs the receipt and halts after commit; a third retries without a second audit. The original process uses the real JPA reader and reconciler to resume after the saved listen without redelivery. Separate PostgreSQL tests cover rollback after audit insertion, concurrent recovery, mismatched retained facts and audit failure.

This transaction assumes the audit and inbox tables are on the same PostgreSQL datasource and that its runtime role can append to the audit chain and update deliveries. The audit chain lock is held until the acknowledgement transaction commits, so contention can delay recovery; failure keeps recovery closed. The acknowledgement is local audit evidence, not proof of remote audit delivery, chain verification, caller authority or permission to dispatch.

The callback and human authorization in the checkpoint test are fixtures. The original checkpoint-writer JVM remains alive and workflow restoration occurs within it. Writer-process death after checkpoint, full application restart, production dispatch, authorized replay, task lifecycle and complete T02/T13 remain open.
