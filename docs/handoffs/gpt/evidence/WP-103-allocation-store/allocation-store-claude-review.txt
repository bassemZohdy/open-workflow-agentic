- **Identity and retries:** `same()` compares the whole `ResourceTaskAllocation` (full scope, contract and profile), so a changed retry throws a conflict. A concurrent first insert uses `on conflict do nothing`, then re-reads and compares.

If both the work and the resume fail, the work failure is primary and the resume failure is suppressed. If only the resume fails, the call throws `StoreUnavailableException`.
