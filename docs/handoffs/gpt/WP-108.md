## Design and corrections to preserve

1. Derive a stable key from persisted tenant/user/run scope, node and logical
   operation occurrence. A loop needs an occurrence identity; transport attempts
   and process restarts must reuse it. Do not include `resume_epoch`: it changes
   on recovery and would permit a second business effect. Section 9.7 of
   `docs/lifecycle.md` currently conflicts with WP-108's stable-key requirement
   and ADR 0023. Correct the current documentation during implementation; do not
   rewrite applied V35 merely to correct its historical comment.
2. Commit intent independently before calling the target. A caller's later
   rollback must not erase it. Reject failed persistence, conflicting targets
   and mismatched request fingerprints before any target call. Define where
   the immutable request fingerprint lives; `Effect` does not contain one today.
3. Enforce key uniqueness and legal state transitions in PostgreSQL transactions.
   Duplicate intents return stored state; competing outcome writes cannot undo
   a terminal state. Never hold a database transaction open over a network call.
4. Do not interpret an existing INTENDED row as permission for an unsafe resend.
   Bound concurrent execution/recovery claims. After a lost acknowledgment,
   query the target or repeat only with the same target-supported idempotency
   key. A timeout alone cannot prove FAILED. A target without safe replay or
   authoritative lookup leaves a durable manual-resolution item and blocks
   automatic re-execution. Target key retention must cover the recovery window.
5. Persist compensation intent separately, with its own stable key and link to
   the original effect. Record COMPENSATED only after confirmed compensation.
   Failed/uncertain compensation remains visible and retry-safe; it cannot be
   represented by marking the original compensated in advance.
6. Persist manual-resolution reason, evidence and decision with concurrency
   control. No unauthenticated operator endpoint is introduced. Public operator
   actions wait for Claude's verified-caller/PEP integration; request that seam
   through a handoff and keep the package partial if it is not yet available.
7. Publish the resulting port, schema and failure fixtures before WP-105's
   effect-aware recovery gate closes. Preserve readiness failure on recovery
   errors; never substitute replay-from-start for arbitrary resume failures.

Use the existing PostgreSQL 16/JDBC stack. PostgreSQL's READ COMMITTED conflict
semantics require care: an INSERT ... ON CONFLICT DO NOTHING can lose to a row
not visible to that command's snapshot. A subsequent read/locking operation
must establish the stored intent; do not assume a same-statement fallback SELECT
always returns it. Validate this with independent concurrent connections.

## Required implementation evidence

| Case | Required result |
|---|---|
| Intent transaction fails | Zero target calls |
| Concurrent duplicate intent | One durable intent; same target/request enforced |
| Conflicting request or target | Refused before execution |
| Crash after intent, before send | Recovery uses the same logical operation/key |
| Target commits, acknowledgment lost | T03: recovery confirms one business effect |
| Outcome write fails after target success | Intent survives; no new key or blind resend |
| Restart with increased resume epoch | Same key and one business effect |
| Two recovery workers | No conflicting outcome or unsafe duplicate dispatch |
| No idempotency/lookup support | Durable manual queue entry; no automatic resend |
| Compensation acknowledgment lost | Same compensation key; final state only after proof |
| Compensation fails | Durable unresolved/manual state, not false success |
| Forged/cross-scope operator action | Denied by verified caller/policy integration |

Run relevant contracts, PostgreSQL and process-kill tests and the repository
verification commands in CONTRIBUTING. T03 must carry `@Acceptance` for M06/M07
and pass CI before its status becomes automated. Record actual commands and
results here when implemented; do not substitute this table for passing tests.
