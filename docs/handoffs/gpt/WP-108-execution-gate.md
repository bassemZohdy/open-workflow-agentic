# WP-108 JDBC fresh-entry callback gate

Base main561c691 includes the reviewed V76 data schema. This adds an explicitly constructed internal `JdbcResourceExecutionGate`; no CDI bean, legacy admission bridge, configured producer, graph adapter or default live fence is activated. WP-108/T03/full Flow acceptance remain partial. V77-V80 are unchanged.

The private-minted Attempt owns an exact binding/full entry/executor and a required trusted `ResourceExecutionFence` supplied as a Java control argument, never workflow or HTTP metadata. Binding/entry are DATA, not verified authority; production composition must supply the real opaque witness, current identity/PDP/audit plus registry/full-owner/definition/actual-task/approved-target/lease checks. Test fences are explicitly fixture-only and establish none of those current-authority claims.

Attempts are admitted under an explicit 1..1024 bound with no queue and no new worker threads. Per-call or gate close invalidates promptly; an unstarted attempt retires immediately, a running attempt holds its slot and fence until its synchronous execute call actually exits. Interruption is checked without clearing its flag. Each attempt can execute only once. Callback work must finish synchronously: arbitrary returned futures or detached workers are unsupported and require a separate actual-termination protocol. This is not the async Flow propagation proof.

The gate verifies exact issuer/jti binding metadata and canonical scope using the existing JDBC row decoder (only package visibility changed). V76 performs immutable call/occurrence/registry/binding/deadline checks on fresh insert. A short owned READ COMMITTED transaction is isolated from ambient JTA. Existing transactions on a borrowed connection are refused rather than committed/rolled back. After insertion, commit, connection close and ambient resume ALL must acknowledge before a callback is eligible. A commit/close/resume failure after commit was attempted is UNKNOWN; even successful same-call readback is retained DATA and never another fresh callback. No reset, new epoch, delete or failed-callback retry API exists.

Only a freshly inserted row reaches the private fresh branch. Concurrent losers, exact repeats and refreshed credentials return retained data without callback. Different retained epochs/full scopes refuse. Required trusted fence runs before storage, after all commit/cleanup/resume work immediately before callback, and after callback before returning its private value. Close/interrupt is rechecked after a blocking fence. Callback failure, post-commit revocation, output refusal or close leaves the entry intact. Historical `find` remains a DATA read, not permission or proof of non-entry; it cannot invoke work. Results redact callback output in toString.
