An absent budget refuses, even with no checkpoint: there is not yet a trusted task-start producer that can distinguish new work from pre-upgrade attempts.
- Implemented: The opt-in V78 resource-task allocation store creates the node budget atomically with a fresh allocation, using its approved model agent, canonical resource thread, retained contract and original allocation deadline. Exact allocation retries never reset the budget; an older allocation without one is not backfilled. V78 remains a proposal and this is not a live production approval or execution source.
- Implemented: A budget-table grant template separates trusted allocation INSERT from executor SELECT and step-only UPDATE. Disposable non-owner PostgreSQL roles prove permitted consumption and refuse creation by the executor, reset, deletion, schema changes and role assumption. This is local grant evidence, not deployed datasource or role configuration.
- Implemented: An opt-in governed model consumer now connects a live execution and exact node request to the V79 full-ceiling reservation gate. It checks the retained allocation, gateway-owned policy and approval, and requires a trusted transport to bind its configuration and enforce a conservative price, output-token ceiling, database-clock deadline and one physical attempt. Existing providers do not implement that contract; real approval, transport, node production, production activation and measured usage remain open.
- Implemented: An explicitly registered PostgreSQL tool budget shares the task's immutable binding and original database-clock deadline. Admissions are independently committed, atomic across instances and never reset on reopen; the local tool gateway requires the budget before invoking a callback. The opt-in V78 allocation adapter can atomically create the tool budget with a fresh allocation and node budget, and refuses missing or mismatched historical budgets. The caller must supply a genuinely approved ceiling; production approval and deployed role separation remain unwired. Canonical tool occurrences and opt-in effect-ledger integration exist but are not yet connected to production dispatch.
- Implemented: A profiled allocation variant retains immutable approved tool configuration data, permitted tools, call count and time ceiling with a fresh task and budget. Exact retries compare every retained field; legacy rows are not backfilled. The opt-in local gateway checks the retained profile and exact registered schema, timeout, effect declaration and supplied implementation digest before and after tool execution. Constructing the data does not prove approval or that an implementation digest identifies deployed code.

Remaining gates:

- Implement durable shared token, cost and tool-call accounting across retries and restarts; enforce the full budget at all relevant gateways and graph boundaries.
- Activate and wire the trusted resource-task allocation and approval path, establish a safe rolling-upgrade path and deployment grants, and prove process-loss, multi-replica and in-flight deadline behavior.
- Add durable exhaustion escalation and prove T06 across all budget dimensions.
