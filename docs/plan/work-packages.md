### WP-001 Repository foundations

Make the structure of the code enforce the architecture.

Deliverables:

- Maven multi-module layout: oa-contracts (pure Java), oa-runtime, oa-control, oa-eval, oa-testkit, deployable apps
- ArchUnit rules: runtime never depends on control; contracts depend on nothing
- Licence and dependency policy check in CI
- API conventions: RFC 9457 errors, correlation id, ULID ids, pagination
- CI with Postgres service; dev compose; CONTRIBUTING

Reuse: Quarkus platform BOM, ArchUnit, Maven enforcer

Notes: Keeps the current sample working while moving it into modules; no behavior change.

### WP-002 Acceptance-test harness

Turn the 39 tests from a document into executable, traceable tests.

Deliverables:

- @Acceptance("T12") annotation and JUnit extension
- Generator that updates test-status.json from surefire reports; CI fails on regressions of automated tests
- Scriptable model double (scripted answers, injected failures, token counts)
- Fault injection: kill and restart the app process, pause the database, delay or drop calls, advance a test clock
- Fake IdP and fake policy service for isolated tests

Reuse: Quarkus test framework, Toxiproxy-style proxy or in-process fault wrapper

Notes: Local sandbox has Postgres but no Docker daemon, so process-level fault injection must not need Testcontainers.

### WP-003 Spike A: Quarkus Flow capabilities

Learn what Quarkus Flow 1.2 really provides for our requirements.

Deliverables:

- Written findings plus characterization tests
- ADR on how instances are started, queried, cancelled and resumed

Reuse: quarkus-flow-jpa, quarkus-flow-durable-kubernetes, quarkus-flow-scheduler, quarkus-flow-messaging

Notes: Questions: start by API with input; listen and emit events with durable resume after restart; timeouts and deadlines; two versions of one definition running together; instance query and cancel API; schema created by JPA module; Kubernetes lease durability; retries; calling a CDI bean as a function; how MDC and identity propagate.

### WP-004 Spike B: LangGraph4j durability

Prove agent runs can pause and resume safely across restarts.

Deliverables:

- Findings and characterization tests
- ADR on checkpoint scoping and state evolution

Reuse: langgraph4j-postgres-saver, langgraph4j-ag-ui-sdk, langgraph4j-opentelemetry

Notes: Questions: interrupt and resume across restart; checkpoint size and growth; changing the state class between versions; thread id scoping to user, instance and tenant; streaming events; cancellation; parallel branches and subgraphs; connection use of the saver.

### WP-005 Spike C: workflow-to-agent bridge

Choose how a workflow task invokes an agent and how context travels.

Deliverables:

- Prototype of three bridges: HTTP call, in-process CDI function, asynchronous start with callback event
- ADR replacing ADR 0014 or confirming it

Notes: Decision criteria: identity, deadline, correlation and budget propagation; behavior when the agent crashes mid-step; at-least-once versus exactly-once; testability; ability to move the agent out of process later.

### WP-006 Spike D: identity, policy and secrets

Choose the identity provider integration, policy engine and secret store.

Deliverables:

- Prototype: Keycloak token exchange (RFC 8693) for delegated, short-lived tokens
- Comparison and ADR: OPA sidecar, Cedar embedded, or Quarkus security policies with custom rules
- Fail-closed behavior and decision latency measured
- Secret store choice (Vault or Kubernetes secrets) with rotation

Reuse: quarkus-oidc, quarkus-flow-oidc, Keycloak, OPA or Cedar

Notes: Needs a decision from the owner about the identity provider already in use.

### WP-007 Spike E: MCP, A2A and agent protocols

Establish what is usable today for tool and agent interoperability in Java.

Deliverables:

- Findings on quarkus-langchain4j-mcp (1.14 vs 2.0 beta), secured MCP auth providers, MCP registry
- Findings on A2A Java SDK and Apicurio registry integration
- Findings on AG-UI for streaming to a UI

Reuse: quarkus-langchain4j-mcp, quarkus-langchain4j-oidc-mcp-auth-provider, quarkus-langchain4j-a2a-apicurio-registry, langgraph4j-ag-ui-sdk

Notes: No A2A client artifact was found in the Quarkus LangChain4j group; the A2A SDK may be used directly.
