**Version:** 6.2 (proposed) · **Date:** 2026-10-18

Source of truth: [`requirements.json`](requirements.json). This file is generated by `tools/render_requirements.py`; edit the JSON, not this file.

34 Mandatory (M), 25 High (H), 5 Optional (O); 8 scenarios, 39 test cases. See [test-cases.md](test-cases.md) and [traceability.md](traceability.md).

## Principles

1. Select outcomes and evidence before implementation strategy
2. Three logical responsibilities do not imply three deployed planes
3. Production promotion and execution authorization must be non-bypassable
4. Durability, effect safety and progress consistency are independent guarantees
5. A versioned OWS artifact is preferred, but not a Mandatory technology choice
6. Existing runtime state can be authoritative; no universal physical task-ledger mandate
7. Security controls are mandatory for capabilities deployed, not a mandate to deploy optional capabilities
8. Open source and avoidance of provider lock-in must be transparently scored
9. Agentic capability is the reason for the solution: agents must be able to plan, use tools and knowledge, collaborate and converse, and workflow guarantees bound them rather than replace them

## Deployment profiles

Profiles switch extra requirements on for specific deployments.

| ID | Profile | Effect | Activated when |
|---|---|---|---|

| P3 | High-impact decisions | Extra oversight, reviewer explanations (H06) and appeal pathways as required by approved internal policy or law | Process has legal or similarly significant consequences |
